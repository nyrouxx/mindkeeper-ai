# Безопасность и личные данные

В публичный репозиторий и архив релиза входят только исходники интеграции.
Файлы `.storage`, `.personal_secretary`, `auth.json`, базы задач, история сообщений,
токены Telegram/Google/ChatGPT и резервные копии не публикуются.

Дела и история хранятся в конфигурации Home Assistant. Текст сообщений и выбранный
контекст отправляются только выбранному AI: через Codex CLI, облачный API или
на указанный локальный сервер. Автоматического переключения между провайдерами нет.
Google Calendar и Telegram используют штатные интеграции HA и их авторизацию.

API-ключи провайдеров хранятся отдельно в приватном атомарном хранилище HA и не
возвращаются в WebSocket-снимки, формы, сенсоры или ошибки. Ключи не передаются
модели в тексте промпта. Проверка подключения использует синтетический контекст
без пользовательских дел. HTTP-запросы не следуют перенаправлениям; сообщения
ошибок фиксированы, ответы провайдеров и заголовки авторизации не журналируются.

Codex запускается без shell-инструментов, плагинов, apps/MCP, браузера и доступа
к исполнительной среде текущей сессии. Он возвращает только структурированный план
изменений, который проверяется и применяется интеграцией. Панель доступна
администраторам HA; входящие Telegram-сообщения ограничены выбранными ботом, чатом
и собеседником. Локальный планировщик не вызывает модель для напоминаний и завершений.

Не прикладывайте к публичным issues `auth.json`, содержимое `.storage`, токены,
пароли, необработанные логи авторизации или снимки задач с личными данными.
Если секрет уже опубликован, отзовите его у соответствующего поставщика.
Для сообщения об уязвимости используйте приватный канал GitHub Security Advisories,
если он доступен в репозитории, либо сначала откройте issue без технических деталей
и личных данных с просьбой о приватном контакте.
